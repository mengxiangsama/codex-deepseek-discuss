# 单模型 / 双模型任务对比

## 当前结果：尚无真实模型 A/B 数据

已加入一个可运行的**支付回调 / 超时关闭业务规则评测**，8 个固定案例，覆盖先支付、先关闭、重复回调、重复关闭与不同付款事件退款。它是贴近实际开发问题的人工构造任务，**不是来自生产项目的数据集，也不是项目级代码修复能力评测**。不能把这 8 题的成绩外推成“双模型更强”。

当前只完成离线评分器和业务规则验证。本次运行环境未配置可用的 DeepSeek API 凭证和付费运行授权，本次没有调用付费 API。单模型结果、双模型结果、模型耗时和实际费用均为**未测**，不是 0，也没有获胜结论。离线测试报告在 [results/offline-check.json](results/offline-check.json)。

## 公平执行协议

1. 固定仓库提交、`orders.json`、Codex 主模型/推理设置。推荐每组至少 3 次，交替顺序（single/dual、dual/single），保存所有失败与截断，不只挑最好结果。
2. 每次使用全新会话，只给模型 `orders.json` 全文，不给 `compare.py`、测试、答案或其他轮次结果。最好在不含评分器的空工作区进行。该数据集公开，因此只能用于透明的工作流试验，不能视作隐藏基准。
3. 单模型：Codex 独立完成，不调用 DeepSeek。双模型：同样的 Codex 设置和任务，DeepSeek 先独立分析，再交换 Codex 的具体选择与分歧、逐项回应并确认最终答案。预先固定最多 3 次 DeepSeek 调用；预算内不一致应记录为未解决，而不是宣称共识。
4. 每组允许同样的工具和任务上下文；唯一差异是双模型的讨论。最终答案在评分前冻结为 JSON。不要看到评分后修改同一轮答案。记录最终答案以外的完整审查过程，才能核验是不是实质讨论。
5. 评分是每个案例的三个字段全部正确才通过。它只衡量规则执行正确性，不衡量解释、设计质量或真实数据库并发安全。

## 运行（不自动调用模型，不执行模型生成的代码）

在仓库根目录，开始计时后立即发任务：

```bash
python benchmarks/compare.py start --arm single --model '实际模型与推理设置' --out single-start.json
```

将模型最终 JSON 原样保存到 `single-answer.json`，把脱敏后的会话记录保存为 `single-evidence.txt`，立即结束计时并评分：

```bash
python benchmarks/compare.py finish --start single-start.json --answers single-answer.json --evidence single-evidence.txt --out single-run.json
```

双模型独立重复以上流程，将 `single` 换成 `dual`，使用 `--arm dual`。生成对比：

```bash
python benchmarks/compare.py report single-run.json dual-run.json
```

耗时是从 start 到 finish 的 UTC 墙钟时间，**包含人工复制、讨论及保存文件时间**，不是纯 API 延迟。请保持操作方式一致，并另外在记录中注明人工暂停；电脑时钟应保持同步。数据集 SHA-256 防止两组任务版本被混用。没有同版本两组数据时 `comparable=false`；它仅表示组别齐全，并不证明方法公平或统计显著。

记录是本地用户提交的证据，不是可信计费或模型身份认证。工具检查格式和计算结果，但不会自动核实会话的真实性、模型身份、讨论轮数或费用。`--model` 是操作者声明，模型提供商的响应标识应另存于证据。文件默认拒绝覆盖，避免意外抹掉旧结果。

## 费用与证据

- 只有**整轮实际费用已知**时才传 `--cost-usd 0.0123`，单位 USD；否则省略，保持 `null`。不要将 DeepSeek 部分费用冒充整轮总费用。
- Codex 订阅通常没有可直接归因的每任务实际费用；记为未知，不能记成免费。可以另外披露订阅情况，但不要随意把月费按 token 分摊。
- 双模型证据应逐次保存 `requested_model`、`response_model`、`response_id`、`finish_reason`、原始 `usage`、调用起止时间和调用结果（包括超时）。服务端未返回的信息写未知。
- 若按公开单价估算 DeepSeek 成本，应记录单价来源、获取日期、币种、缓存命中/未命中 token 与输出 token，并明确标“估算”。它不等同于账单；不能直接用美元参数存入人民币值。最终账单可能含超时请求费用。
- 只保留本任务必要的脱敏上下文。提交仓库前人工检查，勿上传凭据、客户数据或无关历史。报告保存哈希用于核验对应文件，不上传原始会话。
- 答案 JSON 形状错误会报错；该轮依然应保留为失败记录，不要悄悄重试替换结果。当前汇总只接收成功生成的评分记录，格式失败/调用失败次数需在研究报告单独披露。

## 扩展与局限

这是最小可复现实验入口。真正验证项目收益还需增加独立的真实仓库修复任务，使用冻结的回归测试、盲审和多轮试验；预先约定成功标准和时间/费用预算。简单任务可能两组全对，不能据此推断复杂项目无收益。当前不提供自动付费运行器，避免意外开销。
